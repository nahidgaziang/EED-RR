# Data

## `SDSC-SP2-1998-4.2-cln.swf.gz`

The cleaned SDSC-SP2 workload log (IBM SP2, San Diego Supercomputer Center, April 1998 – April 2000) from the
Parallel Workloads Archive: <https://www.cs.huji.ac.il/labs/parallel/workload/l_sdsc_sp2/>. It is redistributed
unmodified, and its copyright notice is preserved in the file header. The licence permits use, copying and
distribution for educational, research and non-profit purposes provided that the notice is kept and the data are
properly referenced. Please cite:

> Feitelson DG, Tsafrir D, Krakov D. Experience with using the Parallel Workloads Archive.
> J Parallel Distrib Comput. 2014;74(10):2967–2982. doi:10.1016/j.jpdc.2014.06.013

and acknowledge the SDSC (Victor Hazlewood). In this study, job run times are used as CPU bursts and submit times
as arrivals, rescaled to a target load. The trace is a proxy for heavy-tailed demand, not a CPU-burst trace.

## `process_data.csv`

The 10,000-process dataset used in the earlier version of the study (the "original dataset" scenario). It was
generated by the earlier `generate_process_data.py` from rows 501–10,500 of the Kaggle dataset
*Scheduling using round robin* by ppmpreetham (`scheduling_data.csv`, 1,000,000 rows, 66,958,400 bytes, MIT
License; <https://www.kaggle.com/datasets/ppmpreetham/scheduling-using-round-robin>). Each Kaggle
row summarises a **simulated** 10-process scheduling run; one process was drawn per row from a Gaussian whose
parameters are linearly rescaled from that row's burst and arrival statistics (burst mean → [20, 380], burst SD →
[8, 55], arrival mean → [2.5, 100], arrival SD → [2, 18]; bursts bounded to [10, 400] and rounded to integers,
arrivals bounded to [2.5, 100] and rounded to quarters; seed 20260610 + 1). Columns: `Process`, `Burst time`,
`Arrival Time`, and `Arrival Time(normalized)` (= arrival / 100). The paper uses the ten consecutive 1,000-row
partitions descriptively only; they are not independent replications.

The Kaggle source file (67 MB) is not redistributed here; download it from Kaggle if needed.

All synthetic workloads are generated on the fly from fixed seeds (`eedrr_bench/workloads.py`) and need no files.
